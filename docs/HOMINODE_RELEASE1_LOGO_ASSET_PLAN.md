# Hominode Release 1 — logo and branding asset plan

Prepared 2026-10-21 (Asia/Manila). **Planning only: no artwork, configuration or application code changed.** Candidate filenames establish availability, not final design approval. Do not interchange Admin, Resident and Security symbols.

## Decisions required before implementation

1. Confirm the final Admin identity: the mobile login currently uses a gold building/ADMIN mark, while native icons and Admin Web use the metallic H/person-and-gear identity. Admin Home separately uses the approved geometric node and HOMINODE wordmark; preserve its layout and mark unless explicitly approved for replacement.
2. Confirm Resident keeps the metallic H/family identity. `Resident_New3.png` is **byte-for-byte identical** to the currently used `Resident_New1.png` and Resident Web `public/images/logo.png`. It is not a new visual update. The gold `Resident_New4.png` is a different design and requires explicit approval.
3. Confirm Security adopts the metallic H/shield-and-lock identity throughout. Current login/startup uses a gold gate/shield tile, while generated native icons already use the metallic H. `Security_New1.png` supplies a transparent H variant, but replacing the gold login artwork is still an identity decision.
4. Approve opaque icon background colors independently from transparent UI marks. Existing generator inputs do not reproduce all current generated icons. Do not run the generators until those differences are resolved.

## What is technically ready versus still missing

**Can be prepared without graphic redesign once identity/background approval is given:** lossless copies; proportional downscaling; transparent padding; opaque launcher compositing onto an approved color; complete native size sets; website favicon/touch exports; stable-path wiring. Resident New3 needs no new replacement at all. Existing Admin Web and Security New1 provide transparent role-specific artwork without automatic background removal.

**Still requires approval or supplied final art:** Admin mobile gold-versus-metal choice; Resident gold New4 versus existing H/family; Security gold login versus H/native reconciliation; Resident white-versus-navy iOS background; native branded splash additions; icon mask/padding/glow treatment; any simplified favicon or themed monochrome symbol; any proposal to replace Admin Home's geometric mark or add artwork to Security's text header. Do not flatten an opaque background into a header or remove intentional glow/details as a convenience.

## Implementation and acceptance sequence — future work only

1. Approve one identity and an opaque icon background per role. Record a hash-to-role mapping, including the current native-output discrepancies. Keep four candidates and all other untracked files untouched.
2. Create separate approved working derivatives (for example `APP/assets/branding/` or its existing asset-root equivalent), never overwrite the original candidates. Update the launcher configuration to point at the selected role-specific icon/foreground sources; review generated diffs platform by platform.
3. Integrate only active Flutter surfaces and approved Vite logo/favicon targets. Keep Admin Home proportions and all business/navigation code unchanged. Do not sweep alternate demos, receipts or desktop targets into the change implicitly.
4. Verify image dimensions/alpha, catalog/resource references, mask/padding and all relevant asset declarations. Reuse Admin `test/logo_asset_test.dart` and Resident Home-logo tests; add focused role/source assertions if implementation changes paths.
5. Inspect real Android launcher masks and Android 12+ light/dark launch transitions, iPhone/iPad launcher and cold launch, login/Home at normal/enlarged text, and web login/sidebar/favicon at 16/32 px. Use white/navy/green backgrounds for transparent edges. Browser and launcher icon caches must be accounted for without clearing authentication/app data unnecessarily.
6. Run only relevant widget/web asset tests, scoped analysis, formatting and diff checks after implementation. Native icon changes require rebuilt apps; Vite asset updates require a later approved Hosting release. No deployment is authorized here.
